# 阶段 0：基础与复盘

## 概念解释

- Python 虚拟环境把项目依赖与系统 Python 及其他项目隔离；锁定直接和间接依赖版本有助于重复安装，但不保证不同操作系统或未验证机器一定兼容。
- FastAPI 提供路由和 OpenAPI 文档；当前 `/health` 只反映进程能返回响应。
- OpenAPI 是描述接口路径、方法与数据结构的机器可读规范；Swagger UI 根据规范生成可交互的文档页面。当前健康接口的返回注解为 `dict[str, str]`，不是单独定义的 Pydantic 响应模型。
- 浏览器访问 Vite，Vite 开发代理把 `/health` 转发给后端；浏览器看到的是同源请求。生产环境需要另行配置代理或明确 CORS 策略。

## 关键设计

单仓库、最小 FastAPI + Vue/TypeScript 骨架便于理解；目前不引入模型、数据库或 Worker。Vite 代理适合本地开发，独立跨域请求与 CORS 是另一种方案。依赖版本固定，npm 使用锁文件；Python 的完整版本清单是本机安装结果。

## 亲自实验

按照 README 启动后端和前端，打开页面并观察状态。再停止后端、刷新页面，观察变化；随后重启后端。也可访问 `/health` 和 `/docs`。如果默认端口被占用，按 README 使用替代端口。

## 实验复盘

- Codex 实测：Windows x64、Python 3.11.6，后端测试 `1 passed, 1 warning`；Node 24.15.0，前端构建成功；HTTP 直接与代理访问均返回 `{"status":"ok"}`。
- 浏览器实测：后端启动时显示“后端已连接”；关闭后端并刷新时显示“后端未连接”。本机路径包含 `#`，按 README 使用目录联接及 Node 保留联接路径选项后正常显示。用户自己的观察、失败和修复：待用户填写。
- 干净机器复现：Unverified；训练、模型效果与性能：Not measured。
- P0-01 用户回答：解释了间接依赖可能产生版本差异、Vite 转发与跨源请求，以及适配层统一模型加载和输入输出；已补充虚拟环境隔离依赖，但不自动安装或选择 Python 版本。
- P0-02 验证：`/health` 和 Vite 代理均返回 200 与 `{"status":"ok"}`；`/docs` 返回 200，OpenAPI 3.1 包含健康接口；浏览器显示连接状态，关闭后端并刷新后显示断开。页面仅加载时检查一次。
- P0-03 实验：在 `backend` 运行 `.\.venv\Scripts\python.exe -m pytest -q` 检查真实的 FastAPI 路由；在 `frontend` 运行 `npm test`，Vitest 用模拟的 `fetch` 响应检查 Vue 页面，不依赖正在运行的后端。本机当时的结果分别为 1 项和 3 项通过；前端构建也通过。模拟测试不能替代之前实际启动两端的浏览器检查。
