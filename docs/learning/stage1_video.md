# 阶段 1：视频上传与元数据

## 概念解释

MP4 是容器，`ffprobe` 可以读取其中视频流的宽、高、平均帧率和时长。`duration_ms` 是以毫秒表示的时长；读取元数据不会证明整段视频每一帧都能解码。

## 关键设计

上传时先分块写入临时文件并限制字节数，然后用 `ffprobe` 检查 MP4 和时长；成功后用随机 ID 保存文件，并将元数据写入 SQLite。接口只返回 ID 和元数据，不返回本地路径。数据库和文件默认保存在 Git 忽略的 `data/` 中。

## 亲自实验

启动后端，打开 `/docs`，上传自己有权使用的一段短 MP4；将返回的 `video_id` 填入 `GET /api/v1/videos/{video_id}`。启动、限制配置和测试命令见 README。

## 实验复盘

- Codex 以 FFmpeg 生成纯色视频测试：1 秒、64×48、5 FPS；真实 HTTP 上传返回 201，查询返回 200 且元数据一致。
- 后端测试 12 项通过，涵盖上传查询、格式和大小时长限制、边界值、缺少 ffprobe、数据库错误清理；pytest 有 1 条 Starlette/AnyIO 弃用警告。
- 用户自己的文件与观察：待填写；没有使用或读取公司视频。
- 上传限制在应用保存阶段生效；multipart 解析的临时空间以及异常断电留下的孤立文件，后续部署或维护时仍需考虑。
